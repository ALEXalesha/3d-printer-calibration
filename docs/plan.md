# Calibrate3dPrinter: план работ

Описание проекта — в `spec.md`. Задачи идут по порядку. Каждая заканчивается зелёными тестами и коммитом.

## Этап 1. Ядро на Python и эталон

1. **Каркас репозитория.**
   - `git init`, `.gitignore`, LICENSE (MIT);
   - README-заготовки EN/RU;
   - `.gitea/workflows/ci.yml` (runs-on: windows; pytest + node:test).
2. **Эталон.** Запустить `reference/calibration.py` во временную папку, а не в `C:\Users\you\All_3d\gcode`: например, подменить `OUT` через копию скрипта в `$TEMP`. Положить 20 файлов в `tests/golden/`. Записать хэши.
3. **Ядро Python** `python/calib3d/core/`. Перенести генератор:
   - класс `Gcode`;
   - тесты-генераторы;
   - `check`, `preview`.

   Убрать глобальные константы (стол, сопло, пруток, откат, разгон, начальный и конечный код, команды прошивки) в объекты «профиль принтера» и «пластик». Закон: эталон байт-в-байт.
4. **Профили в JSON.**
   - `profiles/printers/*.json`: Centauri Carbon проверенный, Generic Klipper/Marlin/RRF;
   - `profiles/materials/*.json`;
   - `profiles/firmware.json` — таблица команд со ссылками на документацию.

   Загрузчик со сверкой схемы.
5. **Шаблоны** начального и конечного кода с подстановками. CANVAS (`M6211`) и M729 — опции профиля Centauri Carbon. Закон: после раскрытия не осталось ни одного `{...}`.
6. **Масштаб по соплу и прутку.**
   - ширина и высота валика, шаги заполнения, подписи;
   - диапазоны тестов, зависящие от сопла: максимальный расход, зазоры.

   Законы:
   - сопло 0.4 = эталон;
   - 0.2, 0.6 и 0.8 проходят проверку G-code.
7. **Проверка G-code** (мини-симуляция). Все пункты из spec.md §7 плюс мутации.
8. **Параметры тестов:** диапазоны и шаги; что-то включено, что-то выключено. Время и граммы для каждого теста.

## Этап 2. Импорт своего G-code

9. **Разбор заголовков** OrcaSlicer, ElegooSlicer, Bambu Studio, PrusaSlicer, SuperSlicer, Cura. Синтетические файлы каждого формата лежат в `tests/import/`.
10. **Начальный и конечный код из файла.** Температуры заменить подстановками, показать отчёт «что найдено и что заменено». Прошивку определять по заголовку или по командам.
11. **Проверка на настоящих файлах Алексея** (`C:\Users\you\All_3d\gcode`, не `ECC_0.4_*`), только локально:
    - начальный код из его последних печатей совпадает с профилем Centauri Carbon по смыслу;
    - в репозиторий эти файлы не класть.

## Этап 3. Версия B — Python с окном (PySide6)

12. **Окно-мастер:** 4 шага / вкладки, темы Paint, RU/EN, окно запоминает место и размер. Пограбли Qt смотреть в памяти:
    - qt-wrapped-label-height;
    - qt-combo-dropdown.
13. **Предпросмотр тестов** (виды сверху и спереди) и помощник результата.
14. **Сохранение:** в папку или архивом; свои профили — в файл.
15. **Тесты интерфейса** offscreen, снимки, сборка exe.

## Этап 4. Версия A — браузер и Electron

16. **Ядро на JS** `web/js/core/`: перенос с Python. Закон одинаковости: матрица профилей, JS и Python дают одинаковый G-code, эталон байт-в-байт.
17. **Страница-мастер** с тем же устройством, что у версии B:
    - темы, RU/EN;
    - профили в localStorage;
    - zip без внешних библиотек или с одной маленькой проверенной.
18. **Импорт G-code в браузере**, предпросмотр, помощник результата.
19. **Electron:**
    - те же файлы;
    - window-state;
    - «Сохранить в папку»;
    - тестовый режим без видимого окна;
    - electron-builder: portable и setup.
20. **Тесты:** Playwright headless, `--workers=1`; снимки всех шагов в светлой и тёмной теме, RU и EN.
