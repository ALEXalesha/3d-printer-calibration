# Calibrate3dPrinter: описание проекта

Дата: 02.10.2026. Автор идеи и владелец: Алексей. Описание для агента, который будет делать проект.

## 1. Что это и зачем

Программа делает готовые калибровочные G-code для **любого** FDM-принтера без слайсера. Это 10 тестов:
- первый слой;
- башня температур;
- поток;
- pressure advance;
- откат;
- максимальный расход;
- нависания и мосты;
- рябь (разгон);
- зазоры;
- кубик 20 мм.

Основа уже есть: `reference/calibration.py`, около 850 строк на Python без зависимостей, и `reference/README.md`. Генератор написан под Elegoo Centauri Carbon (Klipper, сопло 0.4, стол 256 мм). **Все 10 тестов Алексей напечатал 02.10.2026: работают отлично.** Поэтому выход для Centauri Carbon уже проверен на настоящем принтере. Это эталон, его нельзя испортить (раздел 7).

Задача: сделать генератор универсальным, дать ему понятный интерфейс и выпустить как проект с открытым кодом.

Чем проект отличается от уже существующих (сайт Teaching Tech, калибровка в OrcaSlicer):
1. **Автонастройка по своему G-code.** Пользователь загружает файл, который его принтер уже нормально напечатал. Программа сама берёт из него начальный и конечный код, стол, сопло, пруток, прошивку и температуры. Так ошибиться с начальным кодом почти невозможно.
2. Все 10 тестов в одном месте, с предпросмотром и подсказками, как читать результат.
3. Помощник результата: «какая линия лучшая?» → готовое число для профиля слайсера.
4. Русский и английский языки.

## 2. Две версии (решение Алексея)

| Версия | Технология | Где работает |
|---|---|---|
| **A. Браузер + Electron** | одна кодовая база на HTML/CSS/JS без сборщика или с минимальной сборкой | браузерная страница (GitHub Pages и локально из файла) и настольное приложение Electron (portable и setup) из тех же файлов |
| **B. Python с окном** | Python 3.12+, интерфейс **PySide6 (Qt)**; pygame не использовать | настольное приложение, собранное в exe |

Общие правила для обеих версий:
- **Одинаковый результат.** При одних и тех же настройках обе версии выдают байт-в-байт одинаковый G-code. Это проверяют тесты (раздел 7).
- Ядро генератора отделено от интерфейса:
  - A: `core/` — чистые JS-модули без DOM, запускаются и в Node (для тестов), и в браузере;
  - B: пакет `calib3d/core/` — чистый Python без Qt.
- Всё работает без сети, на сервер ничего не отправляется.
- В Electron и Qt окно запоминает место и размер. Модуль окна в Electron — тот же, что у других приложений Алексея (`window-state.js` калькуляторов и «Игротеки»).
- Темы — пять тем Paint, как в калькуляторах (светлая, тёмная и остальные, см. память calculators-themes). Язык RU/EN, переключается и сохраняется.

## 3. Профиль принтера

Поля:
- имя;
- стол X/Y/Z, мм;
- начало координат: угол или центр (у дельт центр);
- форма стола: прямоугольник или круг;
- диаметр сопла: 0.2, 0.4, 0.6, 0.8 и любой другой;
- диаметр прутка: 1.75 или 2.85;
- прошивка: Klipper / Marlin / RepRapFirmware;
- максимальные скорость и разгон;
- откат по умолчанию: длина, скорость, подъём Z;
- начальный и конечный код, шаблоны с подстановками;
- признак «проверен на настоящем принтере».

**Команды, которые зависят от прошивки** (все в одной таблице в ядре, нигде больше в коде):

| Действие | Klipper | Marlin | RepRapFirmware |
|---|---|---|---|
| Pressure / linear advance | `SET_PRESSURE_ADVANCE ADVANCE=v` | `M900 K v` | `M572 D0 S v` |
| Разгон | `SET_VELOCITY_LIMIT ACCEL=a` | `M204 S a` | `M204 P a T a` |
| Температура без ожидания / с ожиданием | `M104` / `M109` | `M104` / `M109` | `M104` / `M109` (или `G10`) |
| Вентилятор | `M106 S0-255` | `M106 S0-255` | `M106 S0-1` (проверить) |

Пометка для агента: для каждой команды найти и записать ссылку на официальную документацию прошивки. Ничего не придумывать: всё, что не проверено по документации, пометить в коде «проверить».

**Подстановки в шаблонах начального и конечного кода:**
- `{nozzle_temp}`, `{first_layer_nozzle_temp}`, `{bed_temp}`;
- `{max_z}`, `{max_z_plus_50_capped}`;
- `{filament_type}`, `{layer_height}`, `{print_title}`.

**Профили в комплекте:**
- **Elegoo Centauri Carbon** — проверен. Начальный и конечный код взять как в `reference/calibration.py`: M729 (чистка сопла), M6211 (система подачи CANVAS) и линия прочистки. Генератор нужно сделать так, чтобы CANVAS (`M6211`) была опцией профиля, а не жёстко зашитой командой.
- **Generic Klipper**, **Generic Marlin**, **Generic RepRapFirmware** — минимальный безопасный начальный код:
  - G28;
  - нагрев стола и сопла с ожиданием;
  - линия прочистки у края стола;
  - без команд конкретных производителей.
- Профили популярных принтеров - см. решение в §11.1 (включить, помечены «непроверено», свой начальный код). Прежний вариант «не включать» отменён. Начальный код из чужих профилей слайсеров (OrcaSlicer AGPL, PrusaSlicer AGPL) копировать нельзя без решения о лицензии. Вместо этого:
  - в интерфейсе крупно предложить «Загрузить свой G-code»;
  - список «непроверенных» пресетов оставить на потом. **Решение за Алексеем.**
- Bambu Lab: у прошивки свои особенности и свои заголовки в файлах. Поддержать только через импорт, с предупреждением «непроверено».

## 4. Импорт настроек из своего G-code

Пользователь выбирает `.gcode` (или `.bgcode`/`.3mf` — это потом, и только если просто). Программа читает:
- **Заголовки слайсеров:** OrcaSlicer, ElegooSlicer, Bambu Studio, PrusaSlicer, SuperSlicer, Cura. Это блоки комментариев `; key = value` в начале или в конце файла:
  - `printable_area` / `bed_shape`;
  - `nozzle_diameter`, `filament_diameter`;
  - `gcode_flavor`;
  - `nozzle_temperature`, `bed_temperature`, `filament_type`;
  - `retraction_length`, `retraction_speed`, `z_hop`;
  - `pressure_advance`, `max_volumetric_speed`.
- **Начальный код:** всё до первого маркера слоя (`;LAYER_CHANGE`, `;LAYER:0`, `; CHANGE_LAYER` и т.п.).
- **Конечный код:** всё после последнего слоя (`;TYPE:Custom` / `; EXECUTABLE_BLOCK_END` и т.п.).
- **Найденные температуры** в начальном коде заменить подстановками и показать пользователю, что именно заменено. Строки он может поправить руками.
- **Если что-то не нашлось,** поле подсвечивается и пользователь заполняет его сам.
- **Прошивка:** по заголовку `gcode_flavor`, а если его нет — по характерным командам (`SET_PRESSURE_ADVANCE` → Klipper, `M572` → RRF, `M900` → Marlin).
- Набор эталонных файлов для тестов импорта сделать самому: короткие синтетические файлы в формате каждого слайсера. Свои настоящие G-code Алексея (`..\All_3d\gcode\*.gcode`, не `ECC_0.4_*`) можно читать для проверки, но **в репозиторий не класть**: там личные пути и имена.

## 5. Пластики

PLA, PETG, ABS, ASA, TPU и «свой». Для каждого:
- диапазон башни температур (сейчас PETG 260→220, PLA 230→190, шаг 5, 9 уровней);
- температура первого слоя;
- стол;
- поток;
- макс. расход;
- вентилятор: обычный, на мостах, сколько первых слоёв без него;
- минимальное время слоя;
- PA по умолчанию.

PETG и PLA взять точно из `reference/calibration.py`: это настройки Алексея, проверенные. Для остальных — разумные общие значения, помеченные «общие».

## 6. Интерфейс

Мастер в 4 шага. Он же — вкладки, по которым можно вернуться назад.

1. **Принтер:**
   - выбрать профиль, загрузить свой G-code или ввести вручную;
   - сохранить свой профиль: localStorage в браузере, файл в настольных версиях;
   - экспорт и импорт профиля в JSON.
2. **Пластик:** выбрать, поправить значения.
3. **Тесты:**
   - карточки 10 тестов с галочками;
   - у каждой предпросмотр (вид сверху и спереди, как `preview()` в эталоне), время печати и граммы;
   - у части тестов свои параметры: диапазон температур, диапазон PA и шаг, диапазон откатов, диапазон зазоров и т.д.
4. **Скачать:**
   - один файл или все архивом (zip);
   - в настольных версиях — «Сохранить в папку»;
   - имена файлов по шаблону `<префикс>_<сопло>_<тест>_<пластик>_<диапазон>.gcode`. Префикс по умолчанию — короткое имя принтера (для Centauri Carbon `ECC`, как сейчас).

Ещё в интерфейсе:
- **Помощник результата:** по каждому тесту понятная картинка, «что искать», и поле «какой уровень / линия лучшая». Программа выдаёт готовое число и куда его вписать в слайсере. Например: PA-линия «024» → `0.024`; плашка потока 104 → коэффициент × 1.04.
- **Порядок печати** — как таблица в `reference/README.md`.
- **Предупреждения:** максимальный расход и рябь печатаются нарочно быстро, за первыми минутами надо следить.
- **3D-просмотр G-code** — по желанию, позже. Например на three.js в версии A и через Qt3D/OpenGL в версии B. Если это заметно удорожает работу — не делать, хватит двух видов.

## 7. Проверки и тесты

- **Главный закон — эталон.** Профиль Centauri Carbon + PETG/PLA при настройках по умолчанию дают G-code **байт-в-байт** такой же, как нынешний `reference/calibration.py` (все 20 файлов). Допустимая разница — только строки заголовка с названием программы и версией, и её нужно явно перечислить в тесте. Эталонные файлы сгенерировать из `reference/calibration.py` и положить в `tests/golden/`. Это сгенерированный код, не личные данные. Но `OUT` с личным путём в репозиторий не тащить.
- **Одинаковость версий.** На матрице профилей (3 прошивки × 3 сопла × 5 пластиков × все тесты, плюс случайные допустимые настройки) ядро JS и ядро Python выдают одинаковый G-code.
- **Проверка G-code** (своя мини-симуляция, общая для обеих версий):
  - всё внутри стола с запасом;
  - Z не выше максимума;
  - скорости и разгоны в пределах профиля;
  - экструзия положительная и правдоподобная (по сечению валика);
  - температуры в пределах пластика и принтера;
  - минимальное время слоя соблюдается (кроме тестов, где скорость — предмет теста);
  - нет «голых» команд другой прошивки (например `M900` в профиле Klipper);
  - шаблоны раскрыты, не осталось ни одного `{...}`.
- **Импорт:** синтетические файлы каждого слайсера → ожидаемый профиль.
- **Мутации:** после каждого блока сломать ядро (поменять знак экструзии, забыть смену температуры, перепутать команду PA) и убедиться, что тесты краснеют.
- **Интерфейс:**
  - версия A — Playwright **только headless, в один поток** (`--workers=1`);
  - Electron — в тестовом режиме окно невидимо и не фокусируется;
  - версия B — Qt offscreen (`QT_QPA_PLATFORM=offscreen`);
  - ни одного видимого окна на экране Алексея.
- Снимки экранов всех шагов в светлой и тёмной теме, RU и EN. Посмотреть их самому.

## 8. Устройство репозитория (предложение)

```
Calibrate3dPrinter/
  web/                 версия A: index.html, css/, js/ui/, js/core/ (ядро, общее с Electron)
  electron/            main.js, preload.js, window-state.js, package.json (electron-builder)
  python/calib3d/      версия B: core/ (ядро), ui/ (PySide6), __main__.py
  profiles/            JSON профилей принтеров и пластиков (общие для обеих версий)
  tests/               golden/, js/ (node:test + Playwright), py/ (pytest)
  reference/           исходный генератор и README, только для чтения
  docs/                spec.md, plan.md, скриншоты
  README.md, README.ru.md, CHANGELOG.md, LICENSE
  .gitea/workflows/ci.yml   (runs-on: windows, как у остальных 13 репозиториев)
```

Профили и пластики — **общие JSON-файлы**, их читают обе версии. Таблица команд прошивок тоже в JSON.
